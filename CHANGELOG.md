# Changelog

Every change to Wayfarer is recorded here: features, fixes, data (each city added or re-ingested), backend, tooling and docs. Newest first. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); sections: **Added**, **Changed**, **Fixed**, **Removed**, **Data**, **Docs**.

How to record a change (enforced in CI by `scripts/check-docs.mjs`):

1. Add a line under **Unreleased** in the same commit as the change — what changed for the user or developer, not how.
2. New or changed feature → also update [README → Features](./README.md#features) (and _Backend reference_ / _Limits and rules_ when relevant).
3. City added or removed → list it under **Data** by name; `docs/CITIES.md` is regenerated by the pipeline.
4. When a milestone or release is cut, rename **Unreleased** to the date / version and start a new one.

## Unreleased

### Changed

- Deploy: this project has no hosted website, so Promote no longer deploys after fast-forwarding `main` and `deploy.yml` is removed. Every production deploy had failed (no Supabase or VPS credentials exist here).
- Deploy: `scripts/deploy-backend.sh` and `scripts/deploy-web.sh` are executable in git, as in travelist; the Promote workflow failed with "Permission denied" whenever it had to deploy the backend.
- Security: `vite` (pulled in by `vitest` in `packages/shared`) is a direct dev dependency at ^8.3.4, past GHSA-587h-7wmj-h5pm (high), so `pnpm audit --audit-level high` passes again.

### Added

- **Desktop app: real executables for Windows and Linux** (D-093): `Travelist-<v>-win-x64-setup.exe` (installer), `Travelist-<v>-win-x64-portable.exe` and `Travelist-<v>-linux-x64.AppImage` open one window that starts the local database (Supabase on Docker), the route functions, the city and trip-planner service and the web app, then shows Travelist. Only Docker is needed on the machine. The keys are one file (**Travelist menu → Edit keys file**). New `desktop/` (Electron, outside the pnpm workspace); `.github/workflows/desktop.yml` builds both systems; `travelist-service` (PyInstaller) packages the Python service, and `TRAVELIST_STATE_DIR` / `TRAVELIST_ENV_FILE` move where it writes and reads.
- **`travelist-service` prints UTF-8**: its help crashed with `UnicodeEncodeError` on a piped Windows console (found by the desktop `--smoke` check).
- **Offline trips** (D-092): **Save for offline** on a trip keeps it on the device — stops, street path and totals, every place with its Wikipedia text, the photos and, on a phone, a map area of the route. With no connection the trip opens from the copy (with a notice), saved places open with their text, My Trips lists the saved trips and **Navigate in the app** keeps working. New `features/offline` (store over real files on a phone and `localStorage` on the web, library of copies, fallback of `useTrip` / `useTrips` / `useAttraction`), `expo-file-system` dependency, EN/PT strings.
- **MongoDB credentials in their own variables** (D-084): `MONGODB_USER` and `MONGODB_PASSWORD` fill the user and the `<db_password>` placeholder of the Atlas string in `MONGODB_URI` (the password is percent-encoded); a string that still has the placeholder and no password variable is reported by name instead of failing with _bad auth_.
- **Releases for Linux, Windows and Android** (D-091): `python -m wayfarer_pipeline release --version <v>` builds `travelist-<v>-linux-x64.tar.gz` and `travelist-<v>-windows-x64.zip`, the local stack in a box (the exported web app, the city and trip-planner service, the database with its data, the route functions, and a launcher: `start.sh` or `start.cmd` / `start.ps1`; they need Docker, Node.js 22 and Python 3.11); the APK comes from `pnpm build:android`. There is no desktop application: the two packages are not installers. `docs/RELEASES.md` has the steps and what was and was not verified.
- **Gemma as the local model** (D-090): `OLLAMA_MODEL` (in the root `.env` or the shell) picks the Ollama model of the trip planner and the suggested routes; `--model` still wins; empty is Qwen. The local install now runs `gemma3:4b`. The pipeline's command line now **reads the root `.env`** (a variable already set in the shell wins), which the integration keys (`SERPAPI_API_KEY`, `ELEVENLABS_API_KEY`, `MONGODB_URI`, `SENTRY_DSN`) needed to reach the service.
- **My city**: the city card now has a **City page** button next to **Explore attractions**; it opens that city's page (`/short/[slug]`: about, prices, people, walk lists, Before you go), for your own city and for a city you searched by name (D-089). `CityHero` takes an optional `onOpenCity`.
- **Estimated prices of every city** (D-088): a city page now has **Estimated prices in {city}** — a beer, a Coca-Cola, a cocktail, a coffee, an inexpensive and a mid-range meal, a typical local dish, a McDonald's Big Mac, a public transport ticket and a taxi / ride of about 5 km, in euros — and **Your day's budget**: sliders for the number of meals (0–6) and drinks (0–10), with a meal style and a kind of drink, give "About €38 a day". **Plan trip** proposals show "About €50 a day for food and drinks" for each city. - **Routes follow the streets, always** (D-087): a route is never a straight line from one stop to the next. `route-optimize` asks OpenRouteService when `ORS_API_KEY` is set and otherwise, or when ORS fails, the public **OpenStreetMap foot router** (FOSSGIS OSRM, no key; `OSM_FOOT_URL` overrides it); with neither it answers **503 `street_routing_unavailable`** and the app says no route was drawn, instead of an estimate across buildings. Response `provider` is now `openrouteservice` or `osm-foot`; `isFallback` is always `false`. A trip saved earlier with a straight-line estimate is not drawn and not navigated along.
- **Navigate in the app** (D-086): a button above _Open in Google Maps_ on a saved trip follows your position with the app open: a blue dot that the map keeps in view, a **Navigating** card with the next stop, its distance and walk estimate, the stops ahead and a warning when you leave the route. The next stop is highlighted on the map and every stop still opens its attraction page, so you can read about a place while navigating (the navigation keeps going). Arriving within 40 m moves to the next stop; **Skip this stop** and **Stop navigating** are in the card; the screen stays awake (`expo-keep-awake`). New `walk-guidance` in `packages/shared` (`stopAfterArrival`, `guidanceTo`, `isOffRoute`, `distanceToLineM`), `features/navigation`, `userPosition` / `followUser` on the map (web and native), EN/PT strings.
- **Visited places** (D-085): **I've been here** on an attraction's page marks it as visited (**Visited** with a tick; tap to undo). Suggested routes then treat it as no priority: a route starts at its nearest stop that is not visited, its card says "N stops already visited", and a route with every stop visited goes last even when it is the nearest. New private table `visited_attractions` (migration `20261012000200`, pgTAP `998_visited_attractions`), `rankByProximity(routes, from, visited)` in `packages/shared`, EN/PT strings.

### Fixed

- **The app could not start with no connection** (D-092): the root screen showed "Loading" until the profile loaded, and with the backend unreachable every screen that asked for the profile restarted its request, which set the query back to pending and swapped the root to "Loading" again, forever, so no screen (not even a saved trip) could open. The profile query no longer restarts when a screen mounts, a profile that cannot be loaded no longer sends a signed-in traveller to onboarding (`canEnterApp`), and it still refetches when the connection returns. Found by cutting the backend in a browser.
- **Sentry Agent Tracing sent nothing** (D-084): with the real `sentry-sdk` 2.x a `gen_ai.chat` span outside a transaction is silently dropped, and the unit tests only used a fake SDK. Each model call is now a transaction (`gen_ai.invoke_agent`) holding the `gen_ai.chat` span with the model and the input / output tokens; a test against the real SDK (events captured, nothing sent) guards it.
- **Planner answers in the wrong language with a small model**: Gemma 3 4B answered a Portuguese request in English because the language was only stated in the system prompt. The language is now repeated at the end of the user message of both calls (`/plan/question`, `/plan/rank`); verified with Gemma (Portuguese question and reasons) and Qwen.
- **Plan trip, "Use my location"** gave no feedback: it now says "Finding your position…" while it waits, then shows where the trip starts from named after the covered city you are in ("Starting from Lisbon"; "Near Lisbon" within 50 km of one, "My location" farther), and explains a refused permission or a failing GPS and points to the city search. Covered by `plan-origin-picker.test.tsx`.
- `scripts/sync-shared.mjs`, `scripts/seed-demo.mjs` and `apps/mobile/scripts/copy-maplibre-worker.mjs` built `C:\C:\…` paths on Windows (so the map's worker and stylesheet were never copied); they now use `fileURLToPath`.
- iPhone layout (D-076), city page: "From Wikipedia" and **Read the full article on Wikipedia**, the Famous people filters and every element of a person's card (name, years, description, "Born here" / "Died here"), the Wikidata credit, "Curated by the Travelist team." and the review form's "Your comment (optional)" label are now centered on phones.
